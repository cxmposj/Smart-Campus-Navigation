Implementation
CampusGraph keeps the existing undirected adjacency list. The new functions use
that same graph, including the original building and neighbor insertion order.

findShortestPath(start, destination, path, error) returns a shortest route.
It uses a queue and a parent vector. An unset parent means a building has not
been visited. The start is marked before entering the queue, and each neighbor
is marked when it is enqueued. The first visit therefore gives the fewest
connections. The route is reconstructed from destination to start using the
parents, then reversed. Neighbor order decides between equally short routes.
Names are trimmed and matched without case sensitivity. Display uses the
original accepted spelling. Failed queries clear the output path.

displayShortestPath(start, destination, out) prints one building per line and
the number of connections, or an error. Same start and destination gives one
building and zero connections. Different disconnected buildings give no path.

displayConnectivityReport(out) prints the building and undirected connection
counts, all highest-degree buildings, isolated buildings or None, and the
number of components. It starts BFS from each still-unvisited building.
An isolated building counts as one component. Empty graphs give zero totals
and an explanatory message.

Both new operations take O(V + E) time and O(V) extra space, assuming bounded
building-name lengths. Endpoint lookup is linear and is included in that bound.
The graph owns its storage through vectors; the searches use local vectors and
queues. No separate graph copy or manual allocation is used.

Shared menu integration
Option 8 in src/main.cpp now reads the starting and destination buildings and
calls campusGraph.displayShortestPath(start, destination, cout). Blank starting
names return to the menu immediately. End-of-input at either prompt exits cleanly.
Option 17 calls campusGraph.displayConnectivityReport(cout) on the same graph.
The existing graph display, degree counts and reachability remain options 5-7.

The standalone tests/graph_demo.cpp is still a graph-only driver. It must not be
linked into the full application because it has its own main function.
Other menu operations, shared input handling and full-project CELL verification
remain with the team integrator. The shared menu currently uses 18 to exit;
UI-7 requires 0, which remains a separate integration fix.
